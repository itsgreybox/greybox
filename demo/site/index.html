The confidence score is arithmetic. Try it.

Every file gets a score out of 100 from four structural signals, worked out before any AI is involved. These sliders use the same formula as the CLI's confidence_score in analyzer.py.

A low score does not mean the file is broken. It means a lot is hidden in it and not much was written down about why, so changing it carries more risk.

if / else / loop paths counted in the file
bare numbers like 1.0475 with no name

Odd rule, on purpose: a file with no flagged comments loses 10 points, and one with a flagged comment gains 5. A comment is a clue about why the code is the way it is.

Your code can stay where it is

The live scanner only reads public repositories. Most real legacy code is private, and some industries cannot send code to a third party at all. That is what the open-source CLI is for.

Runs on your machine

Private GitHub, GitLab, Bitbucket, or code that never lived in a hosted repo. Nothing is uploaded by default.

You control the AI call

The AI explanation only runs if you set your own API key. Skip it and you still get the dependency graph and confidence scores.

A whole portfolio in one run

Point --portfolio at a folder of repos. Every subfolder gets a full scan, ranked into quick wins, bigger efforts and lower priority.

greybox /path/to/org-repos --portfolio --output portfolio_report.md

The web demo's org scan samples a few files per repo to stay inside API rate limits. The CLI has no such cap.
